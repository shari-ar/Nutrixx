# Domain glossary

| Field         | Value                        |
| ------------- | ---------------------------- |
| Status        | Proposed target language     |
| Audience      | All contributors             |
| Owner         | Nutrixx Domain Working Group |
| Last reviewed | 2026-10-10                   |

| Term                          | Meaning                                                                                                              | Important distinction                                                                                                                                              |
| ----------------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Food                          | A consumable catalog item with identity, preparation state, portions, composition observations, and provenance.      | A recipe formula is a separate concept.                                                                                                                            |
| Food composition observation  | A sourced nutrient amount for a food on an explicit basis.                                                           | Its meaning is scoped to its evidence and source version.                                                                                                          |
| Nutrient                      | A canonical analyte or dietary component tracked by the platform.                                                    | Nutrients, bioactives, contaminants, and derived metrics require explicit types.                                                                                   |
| Portion                       | A named or measured quantity convertible to an edible mass or volume under a stated method.                          | “One cup” without food-specific conversion is incomplete.                                                                                                          |
| Recipe                        | The stable identity of a preparation authored or curated over time.                                                  | It has many immutable recipe versions.                                                                                                                             |
| Recipe version                | An exact ingredient, quantity, yield, and method snapshot.                                                           | Editing creates a new version while historical meals retain their recorded version.                                                                                |
| Meal                          | A user event grouping consumed items at a local date/time.                                                           | It represents actual consumption; a recommended plan slot is a separate concept.                                                                                   |
| Meal item                     | A consumed quantity referencing the exact food or recipe output known at logging time.                               | Its captured facts remain auditable after catalog updates.                                                                                                         |
| Observation                   | A value observed or reported at a time with source, unit, and quality metadata.                                      | Clinical conclusions require a separate qualified process.                                                                                                         |
| Target                        | A versioned range or threshold applicable to a defined population and time horizon.                                  | RDA, AI, UL, and Daily Value retain distinct meanings.                                                                                                             |
| Constraint                    | A condition considered by the planner.                                                                               | Hard constraints take precedence over score; soft constraints contribute to score.                                                                                 |
| Objective                     | A normalized, weighted preference optimized after hard feasibility.                                                  | Safety limits are represented as hard constraints.                                                                                                                 |
| Nutrition state               | An internal, versioned estimate of recorded dietary intake and evidence quality for an explicit period.              | User-facing wording follows [ADR-0008](../decisions/ADR-0008-recorded-intake-state-semantics.md); physiological or clinical status belongs to a qualified process. |
| Plan                          | A validated set of proposed meals, portions, and alternatives for a stated horizon.                                  | A plan is a proposal until consumed.                                                                                                                               |
| Optimizer run                 | An immutable execution record containing input snapshot, model, solver configuration, outputs, and diagnostics.      | A run includes the full trace alongside its winning plan.                                                                                                          |
| Provenance                    | The chain connecting a value to source, transformation, policy, and version.                                         | A URL alone is insufficient provenance.                                                                                                                            |
| Confidence                    | A calibrated statement about data or model reliability under defined evidence.                                       | Displayed values require empirical calibration.                                                                                                                    |
| Completeness                  | The extent to which required components have known values.                                                           | Accuracy is measured independently.                                                                                                                                |
| Uncertainty                   | A representation of plausible variation from measurement, composition, portion, or model error.                      | Unknown and uncertain retain distinct meanings.                                                                                                                    |
| Dataset release               | An immutable collection of validated source records and mappings approved for use.                                   | Publication follows validation and approval of staged data.                                                                                                        |
| Rule set                      | An immutable release of scientific formulas, conversions, targets, and eligibility policy.                           | Code version and scientific policy version are separate.                                                                                                           |
| Eligibility                   | Whether the product can safely handle a request within its intended use.                                             | Health status requires an independent assessment.                                                                                                                  |
| Local mode                    | Authority mode in which one browser profile holds the canonical user nutrition database.                             | Recovery uses portable export; synchronization belongs to Cloud mode.                                                                                              |
| Cloud mode                    | Authority mode in which Nutrixx cloud holds canonical user nutrition data and devices synchronize against it.        | Device storage acts as a bounded cache and outbox.                                                                                                                 |
| Canonical authority           | The single writable location whose committed version decides the current user fact.                                  | Authority follows the active lifecycle state.                                                                                                                      |
| Entitlement                   | A versioned, effective-dated grant to use a capability under a plan or exception.                                    | Server-side authorization governs access.                                                                                                                          |
| Usage reservation             | An idempotent temporary claim on a metered hosted action that becomes consumed or released.                          | Domain writes have an independent completion state.                                                                                                                |
| AI action                     | One user-initiated hosted inference attempt with stable identity and usage lifecycle.                                | Provider calls and retries may belong to one action.                                                                                                               |
| Capture draft                 | Structured AI-proposed meal or recipe data awaiting user review and domain validation.                               | Canonical status follows explicit validation and confirmation.                                                                                                     |
| Experimental Local Processing | An explicitly enabled Free advanced setting for user-supplied provider access or device-local WebGPU/WASM inference. | It remains an advanced setting; paid optimizer access follows entitlement policy.                                                                                  |
| Migration session             | A resumable, auditable transition between local and cloud authority using a verified manifest.                       | Verified activation switches authority after upload completion.                                                                                                    |
| Tool invocation               | A typed assistant request to an allowlisted application capability with authorization and audit context.             | Execution requires application authorization and applicable confirmation.                                                                                          |

Terms that carry regulatory or scientific meaning MUST be scoped to a source,
population, geography, and effective version.
